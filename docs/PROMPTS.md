# 从需求到工作台：可复用的提示词

这些提示词按交付阶段重新编写。它们保留了产品决策和验收方法，可在新的开发会话中单独使用。

## 1 · 从真实学习问题开始

> 为中文母语的意大利语学习者制作一个本地听力工作台。素材来自 Online Italian Club，优先核对 A1 专页的每篇课程和全部音轨，保留原题与出处。让用户能盲听、找出没听清的一小段、听写、问课文里的表达，并隔天再次辨认。界面安静、对手机友好，用可操作的反馈鼓励学习者继续。

产出是完整课程入口与原声工作台。先检查多音轨课程，再决定“课程”和“录音”的数据关系。

## 2 · 将教学原则变成需求和工程约定

> 依据首听理解、语音解码、篇章理解、延迟保持和陌生材料迁移整理产品需求。分别定义精听、高变异辨音、元认知训练、连续泛听、间隔听觉复习。把页面与阶段验收写入 PRD，把数据模型、音源能力、字幕可见性与学习记录写入架构文档，把开发约束和回归检查写进 AGENTS.md。清楚区分产品假设、已实现功能和待验证效果。

交付物见 [产品需求](PRD.md)、[技术架构](ARCHITECTURE.md) 和 [开发约定](../AGENTS.md)。

## 3 · 分模块实现

| 负责人 | 可直接使用的任务提示 |
|---|---|
| 播放器 | 实现按音轨隔离的播放状态。提供时间轴、5 秒回退、A–B 循环、遍数、跟读间隔、键盘控制与难段收藏。按实际音源暴露变速能力。测试切轨、自然结束、重复触发及过期回调。 |
| 精听反馈 | 首次隐藏文本，记录初答、信心及是否揭示过文本。只对已核对答案的题目评分。让学习者手选参考句以核对漏词、错词和多写，允许自行修改归因，然后整段重听。 |
| 计划与复习 | 按可用时间和到期片段分配当日任务。卡片先播放音频，提交初答后再展示参考。分别记录自评、可判分的识别与下次到期日。 |
| 集成 | 固定音轨 ID 和片段毫秒边界作为模块契约。验证首页、指定课程链接、刷新、移动端、收藏到复习的完整流程。区分播放器逻辑测试、真实播放进度和人工试听。 |

## 4 · 整理发布

> 以可运行的源码包发布。README 应说明启动方法、学习流程、功能边界、外部服务和学习数据的去向。截图使用空白浏览器配置。核对版权归属、提交身份、打包文件清单及敏感数据；从归档重新解压验证后再上传。
